# Database

The hosted Supabase project is the source of truth for challenge data. All timestamps are stored as
`timestamptz` in UTC and displayed in **Asia/Dhaka (UTC+6)** by the application. The visitor's
browser timezone is never used for challenge dates.

## Schema

### `profiles`

One row per user, keyed by `auth.users.id`.

| Column                | Type        | Notes                                       |
| --------------------- | ----------- | ------------------------------------------- |
| `id`                  | uuid        | Primary key, cascades with the auth user    |
| `real_name`           | text        | Private, nullable, 1–120 chars when present |
| `alias`               | text        | Required, unique case-insensitively         |
| `country_code`        | text        | Optional ISO 3166-1 alpha-2, uppercase      |
| `show_country`        | boolean     | Defaults false; controls public country     |
| `show_on_leaderboard` | boolean     | Defaults true                               |
| `certificate_name`    | text        | User-confirmed print name, nullable         |
| `created_at`          | timestamptz | Server generated                            |
| `updated_at`          | timestamptz | Server generated by trigger                 |

Alias rules: 3–24 characters, lowercase ASCII letters, numbers, and underscores, starting with a
letter. Reserved aliases such as `admin`, `staff`, `support`, `moderator`, `system`, `nnn`, and
`official` are rejected. The unique index uses `lower(alias)`.

### `challenges`

| Column                   | Type        | Notes                                       |
| ------------------------ | ----------- | ------------------------------------------- |
| `id`                     | uuid        | Primary key                                 |
| `slug`                   | text        | Unique, lowercase letters/numbers/dash      |
| `title`                  | text        | Display title                               |
| `start_at`               | timestamptz | Official start in UTC                       |
| `end_at`                 | timestamptz | Exclusive end in UTC                        |
| `timezone`               | text        | IANA timezone, `Asia/Dhaka` for NNN         |
| `registration_opens_at`  | timestamptz | Optional                                    |
| `registration_closes_at` | timestamptz | Optional                                    |
| `status`                 | text        | `draft`, `scheduled`, `active`, `completed` |
| `created_at`             | timestamptz | Server generated                            |

`end_at` must be greater than `start_at`. Registration windows must be ordered.

### `participations`

| Column               | Type        | Notes                                          |
| -------------------- | ----------- | ---------------------------------------------- |
| `id`                 | uuid        | Primary key                                    |
| `challenge_id`       | uuid        | References `challenges`                        |
| `user_id`            | uuid        | References `auth.users`                        |
| `joined_at`          | timestamptz | Server generated                               |
| `attempt_started_at` | timestamptz | Server-controlled                              |
| `attempt_status`     | text        | `active`, `reset`, `completed`, `disqualified` |
| `is_late_joiner`     | boolean     | Server-controlled                              |
| `reset_at`           | timestamptz | Server-generated when reset                    |
| `completed_at`       | timestamptz | Server-generated when completed                |
| `created_at`         | timestamptz | Server generated                               |

One participation per user per challenge. Reset and completion timestamps must agree with the
attempt status. The leaderboard index covers `(challenge_id, attempt_status, attempt_started_at)`.

### `certificates`

| Column             | Type        | Notes                                       |
| ------------------ | ----------- | ------------------------------------------- |
| `id`               | uuid        | Primary key                                 |
| `certificate_code` | text        | Unique random public code, never sequential |
| `participation_id` | uuid        | Unique; one certificate per participation   |
| `display_name`     | text        | Snapshot of the confirmed print name        |
| `issued_at`        | timestamptz | Server generated                            |
| `status`           | text        | `valid` or `revoked`                        |
| `pdf_storage_path` | text        | Optional private storage path               |

The unique `participation_id` makes certificate issuance idempotent.

`admin_audit_log` is intentionally deferred to Milestone 8, when admin actions are introduced.

## Row Level Security

RLS is enabled on all four base tables.

| Table            | Anonymous | Authenticated user           | Service role |
| ---------------- | --------- | ---------------------------- | ------------ |
| `profiles`       | No access | Own row read/insert/update   | Full access  |
| `challenges`     | No access | No access (public view only) | Full access  |
| `participations` | No access | Own row read only            | Full access  |
| `certificates`   | No access | Own certificate read only    | Full access  |

Users cannot insert or update participations directly. Joining and resetting must go through
server-validated operations in later milestones. Users cannot update another user's profile,
participation, or certificate.

## Public views

These views are owned by the migration role and expose only safe columns. Base table access is
revoked from `anon`, and `challenges` is revoked from `authenticated` as well.

### `public_challenges`

Exposes `slug`, `title`, `start_at`, `end_at`, `timezone`, registration timestamps, and `status` for
non-draft challenges. No internal IDs.

### `public_leaderboard`

Exposes `challenge_slug`, `is_late_joiner`, `rank`, `alias`, `country_code`, and `streak_seconds`.

- Only active participations are included.
- Hidden profiles (`show_on_leaderboard = false`) are excluded.
- Country is null unless the participant opted in with `show_country = true`.
- Late joiners are partitioned into a separate rank group.
- Rank is ordered by `attempt_started_at` ascending, which is the published streak-duration
  ordering and tie-breaker. Identical timestamps share a rank.
- No real names, email addresses, internal IDs, or reset history are exposed.

### `public_certificates`

Exposes `certificate_code`, `display_name`, `challenge_title`, `challenge_year`, `issued_at`, and
`status`. No email, user ID, participation ID, or private profile data.

## Applying migrations

The service-role key cannot execute DDL. To apply migrations to the hosted project, add the hosted
Postgres connection string to `.env.local`:

```env
SUPABASE_DB_URL=postgresql://...
```

Get the connection string from **Supabase Dashboard → Connect**. It is a secret: never commit it,
never prefix it with `NEXT_PUBLIC_`, and never expose it to the browser.

Then run:

```powershell
pnpm supabase:push
pnpm test:rls
```

`pnpm supabase:push` runs `supabase db push --db-url` and regenerates `src/types/database.ts`.
`pnpm test:rls` creates temporary test users, profiles, participations, and certificates, verifies
the policies, and cleans them up.
